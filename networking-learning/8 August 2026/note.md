# Jeremy's IT Lab( video 1 to 5)
شبکه چیست؟ (What is a Network?)
خب، شبکه چیست؟
بیایید از دوستانمان در Wikipedia سؤال کنیم:
«شبکه‌ی کامپیوتری یک شبکه‌ی ارتباطات دیجیتال است که به گره‌ها (Nodes) اجازه می‌دهد منابع را با یکدیگر به اشتراک بگذارند.»
خب، اگر قبل از خواندن این جمله متوجه مفهوم شبکه نشده بودید، احتمالاً بعد از خواندن همین جمله هم هنوز کاملاً متوجه نشده‌اید!
پس بیایید بیشتر بررسی کنیم.
در این تعریف گفته شده است که یک شبکه به Nodeها (گره‌ها) اجازه می‌دهد منابع را با یکدیگر به اشتراک بگذارند.
اما Node چیست؟
در اینجا چند نوع از گره‌های شبکه را معرفی می‌کنم. بعضی از آنها را در شبکه‌ی نمونه‌ی اسلاید قبلی دیدید.
________________________________________
Router — روتر
این یک Router (روتر) است.
احتمالاً قبلاً کلمه‌ی Router را شنیده‌اید و یک تصور کلی از اینکه روتر چیست دارید.
اما در این درس وظیفه‌ی روتر را توضیح خواهم داد.
________________________________________
Switch — سوئیچ
این یکی یک Switch (سوئیچ) است.
ممکن است با مفهوم سوئیچ آشنا باشید یا نباشید.
سوئیچ وظیفه‌ای متفاوت از روتر دارد، اما از بسیاری جهات نیز به روتر شباهت دارد.
________________________________________
Firewall — فایروال
نماد بعدی مربوط به Firewall (فایروال) است.
احتمالاً با فایروال‌ها آشنا هستید و به احتمال زیاد یک فایروال روی کامپیوترتان نصب شده است.
این یک Software Firewall (فایروال نرم‌افزاری) است.
اما شبکه‌های بزرگ معمولاً دارای یک Hardware Firewall (فایروال سخت‌افزاری) هستند؛ یعنی یک دستگاه شبکه‌ی جداگانه که به محافظت از شبکه کمک می‌کند.
________________________________________
Server — سرور
این نماد یک Server (سرور) را نشان می‌دهد.
اگر با کامپیوترها آشنا باشید، حتماً قبلاً کلمه‌ی Server را شنیده‌اید.
اما سرورها دقیقاً چه کاری انجام می‌دهند؟
خب، اگر در حال تماشای این ویدیو هستید، این ویدیو را از طریق یک Server روی اینترنت دریافت می‌کنید.
________________________________________
Client — کلاینت
آخرین نماد این اسلاید مربوط به Client (کلاینت) است.
شما برای مشاهده‌ی این ویدیو از یک Client استفاده می‌کنید؛ این Client می‌تواند:
•	گوشی هوشمند
•	لپ‌تاپ
•	کامپیوتر دسکتاپ
•	یا هر دستگاه دیگری
باشد.
اما دقیقاً Client چیست؟
بیایید بررسی کنیم.
در چند اسلاید آینده، یک شبکه‌ی نمونه می‌سازیم و وظیفه‌ی هرکدام از این Network Nodeها را در شبکه بررسی می‌کنیم.
ممکن است اصطلاح Client و همچنین نوع قبلی Node یعنی Server را با نام‌های دیگری مثل:
End Host یا Endpoint
نیز بشنوید.
________________________________________
ساختن یک شبکه (Building a Network)
خب، ما با چند نوع Network Node آشنا شدیم، اما هنوز دقیقاً بررسی نکرده‌ایم که هرکدام از این Nodeها چه کاری در شبکه انجام می‌دهند.
بیایید یک شبکه بسازیم و نقش هر Node را بررسی کنیم.
اینجا دو کامپیوتر داریم:
•	PC1 در سمت چپ
•	PC2 در سمت راست
در حالت فعلی، این هنوز یک شبکه نیست.
اما اگر آنها را با یک کابل به یکدیگر متصل کنیم...
حالا یک شبکه داریم!
بله، درست است.
دو کامپیوتر که به یکدیگر متصل شده‌اند، خودشان یک شبکه تشکیل می‌دهند.
البته این یک شبکه‌ی بسیار ساده است.
اما اگر دوباره به تعریف Wikipedia نگاه کنیم:
«شبکه‌ی کامپیوتری یک شبکه‌ی ارتباطات دیجیتال است که به Nodeها اجازه می‌دهد منابع را با یکدیگر به اشتراک بگذارند.»
حالا که این دو Node به یکدیگر متصل شده‌اند، می‌توانند منابع را به اشتراک بگذارند.
در واقع می‌توانند با یکدیگر ارتباط برقرار کنند.
________________________________________
Clientها
من در اینجا Clientها را با این نماد نمایش می‌دهم.
اما انواع مختلفی از دستگاه‌ها می‌توانند به‌عنوان Network Client عمل کنند.
برای مثال:
•	یک لپ‌تاپ
•	یک کامپیوتر دسکتاپ با سیستم‌عامل Microsoft Windows
•	یک iMac با سیستم‌عامل macOS
•	یک iPhone با سیستم‌عامل iOS
اینها فقط چند نمونه از دستگاه‌هایی هستند که می‌توانند Client شبکه باشند.
بنابراین بیایید یک تعریف ساده برای Client داشته باشیم:
Client دستگاهی است که به سرویسی که توسط یک Server ارائه شده است دسترسی پیدا می‌کند.
خب، از آنجا که Server بخشی از تعریف Client است، برای اینکه Client را کاملاً درک کنیم باید Server را نیز بشناسیم.
پس Server چیست؟
بیایید بررسی کنیم.
________________________________________
Serverها
من از این نماد برای نمایش یک Server استفاده می‌کنم.
وقتی کلمه‌ی Server را می‌شنوید، ممکن است به دستگاه‌هایی مانند این سرور IBM یا این سرور DELL فکر کنید.
و واقعاً هم اینها Serverهای قدرتمندی هستند.
در Data Centerها نیز معمولاً ردیف‌های زیادی از چنین Serverهایی وجود دارد.
اما همه‌ی Serverها این شکلی نیستند.
در حقیقت، هرکدام از Clientهایی که در اسلاید قبلی بررسی کردیم نیز می‌توانند Server باشند!
چطور چنین چیزی ممکن است؟
بیایید دوباره تعریف Client را بررسی کنیم و سپس آن را با تعریف Server مقایسه کنیم.
تعریفی که برای Client داشتیم این بود:
«Client دستگاهی است که به سرویسی که توسط Server ارائه شده است دسترسی پیدا می‌کند.»
بنابراین می‌توانیم این تعریف را تقریباً برعکس کنیم تا بفهمیم Server چیست:
Server دستگاهی است که برای Clientها قابلیت یا سرویس فراهم می‌کند.
حالا بیایید به شبکه‌ی ساده‌ی دو کامپیوتر که با یک کابل به یکدیگر متصل شده‌اند برگردیم.

Serverها و Clientها (Servers and Clients)
این شبکه را به خاطر دارید؟
به این ارتباط کوچک بین دو کامپیوتر نگاه کنید و فکر کنید کدام‌یک Server و کدام‌یک Client است.
PC1 از PC2 درخواست فایل image.jpg می‌کند.
PC2 پاسخ می‌دهد و فایل تصویری درخواست‌شده را ارسال می‌کند.
پس کدام Client است و کدام Server؟
PC1 دستگاهی است که سرویس را درخواست می‌کند؛ یعنی درخواست می‌کند تصویر برایش ارسال شود.
PC2 دستگاهی است که سرویس را ارائه می‌دهد؛ یعنی تصویر را ارسال می‌کند.
بنابراین:
PC1 = Client
PC2 = Server

مثال دوم: YouTube
بیایید یک مثال دیگر از رابطه‌ی Client-Server ببینیم.
در سمت چپ، کامپیوتر شما یا شاید گوشی هوشمند شما قرار دارد؛ یعنی هر دستگاهی که برای مشاهده‌ی این ویدیو استفاده می‌کنید.
در سمت راست، یک YouTube Server قرار دارد که این ویدیو را در خود نگهداری می‌کند.
به نظر شما ابر آبی‌رنگ وسط چه چیزی را نشان می‌دهد؟
پاسخ:
Internet — اینترنت
در نمودارهای شبکه، معمولاً از یک Cloud (ابر) برای نمایش اینترنت استفاده می‌شود.
همچنین زمانی که جزئیات یک بخش از شبکه اهمیت ندارد، می‌توان از Cloud برای نمایش آن قسمت استفاده کرد.
اینترنت یک شبکه‌ی بسیار پیچیده است.
اما برای این نمودار فقط کافی است بدانیم داده از کامپیوتر شما از طریق اینترنت عبور می‌کند تا به YouTube Server برسد.
جزئیات دقیق ساختار اینترنت برای این نمودار مهم نیست، بنابراین می‌توانیم به‌سادگی از این Cloud برای نمایش اینترنت استفاده کنیم.
کامپیوتر شما یک درخواست برای صفحه‌ی YouTube، شامل ویدیو، به YouTube Server ارسال می‌کند.
سپس Server یوتیوب داده‌ها را از طریق اینترنت به کامپیوتر شما برمی‌گرداند.
البته YouTube داده‌ها را یک‌باره ارسال نمی‌کند.
بلکه یک Stream (جریان) از داده‌ها را برای شما ارسال می‌کند تا زمانی که کل ویدیو را مشاهده کنید.

مثال AirDrop
برای یک مثال دیگر فرض کنید می‌خواهید یک ویدیو را از دوستتان دریافت کنید.
هر دوی شما iPhone دارید.
از دوستتان می‌خواهید که ویدیو را با استفاده از AirDrop برای شما ارسال کند.
گوشی شما درخواست ویدیو را ارسال می‌کند.
گوشی دوستتان پاسخ می‌دهد و ویدیو را ارسال می‌کند.
احتمالاً حالا دیگر می‌دانید:
کدام گوشی Client است و کدام Server؟
همان‌طور که حدس زدید:
گوشی شما در سمت چپ Client است.
گوشی دوستتان در سمت راست Server است.
برای مرور دوباره:
Client دستگاهی است که به سرویسی که توسط Server ارائه شده دسترسی پیدا می‌کند.
و:
Server دستگاهی است که برای Clientها قابلیت یا سرویس ارائه می‌دهد.
همچنین به خاطر داشته باشید که یک دستگاه یکسان می‌تواند در بعضی شرایط Client و در شرایط دیگر Server باشد.
امیدوارم حالا درک بهتری از مفهوم Client و Server داشته باشید.
حالا بیایید شبکه را گسترش دهیم و بخش بعدی ارتباط بین End Hostها و اینترنت را اضافه کنیم.

Switchها
فرض کنید این یک شبکه‌ی مربوط به یک Enterprise (سازمان/شرکت بزرگ) است.
این Enterprise یک شعبه در نیویورک و یک شعبه در توکیو دارد.
البته یک شعبه‌ی واقعی یک شرکت بسیار بیشتر از چند کامپیوتر و چند Server خواهد داشت؛ اما من نمی‌توانستم کل یک شبکه را در یک اسلاید جا بدهم!
معمولاً End Hostهایی مانند PCها و Serverها را مستقیماً به یکدیگر متصل نمی‌کنیم.
در عوض، اتصال‌ها را در دستگاهی به نام Switch تجمیع می‌کنیم.
همان‌طور که می‌بینید:
دو PC به SW1 متصل هستند.
و دو Server به SW2 متصل هستند.
Switchها Interfaceهای زیادی دارند تا End Hostها را به آنها متصل کنیم.
به این Cisco Catalyst Switch نگاه کنید.
همان‌طور که می‌بینید، تعداد زیادی Interface یا Port برای اتصال PCها و Serverها دارد.
Switchها برای Forward کردن ترافیک در داخل یک LAN استفاده می‌شوند.
LAN مخفف:
Local Area Network
یعنی شبکه‌ی محلی است.
PC1 و PC2 و همچنین دستگاه‌های دیگری که به SW1 متصل هستند، مانند یک Network Printer یا PC دیگر، همگی در یک LAN قرار دارند.
همین موضوع درباره‌ی دستگاه‌هایی که به SW2 در شعبه‌ی توکیو متصل هستند نیز صدق می‌کند.
بنابراین:
در سمت چپ یک LAN داریم.
در سمت راست نیز یک LAN داریم.
Hostهای داخل هر LAN می‌توانند برای یکدیگر داده ارسال کنند؛ مثلاً:
PC1 → PC2
اما این Switchها نمی‌توانند مستقیماً LANها را به اینترنت متصل کنند یا داده را بین این دو LAN منتقل کنند.
پس بیایید بیشتر درباره‌ی Switchها صحبت کنیم.

ویژگی‌های Switch
در سمت چپ همان Cisco Switch مربوط به اسلاید قبلی را داریم.
این دستگاه یک Catalyst 9200 است.
در سمت راست نیز یک Catalyst 3650 قرار دارد.
Catalyst Switchها، Switchهای Enterprise-grade شرکت Cisco هستند که بسیاری از سازمان‌ها برای اتصال LANهای خود از آنها استفاده می‌کنند.
حالا برخی ویژگی‌های Switch را مرور کنیم:
1. تعداد زیادی Port دارند
Switchها Interface یا Portهای شبکه‌ی زیادی برای اتصال End Hostهایی مانند PC دارند؛ معمولاً 24 پورت یا بیشتر.
2. اتصال Hostهای یک LAN
Switchها اتصال بین Hostهایی را فراهم می‌کنند که در یک LAN قرار دارند.
جزئیات LAN را بعداً بررسی خواهیم کرد.
اما فعلاً بدانید LAN یعنی End Hostهایی که در یک محدوده‌ی یکسان قرار دارند.
برای مثال:
•	تعدادی کامپیوتر در یک طبقه‌ی ساختمان
•	یک دفتر کوچک
•	شبکه‌ی خانه‌ی شما
3. Switch برای اتصال LANها به یکدیگر یا اینترنت نیست
Switchها اتصال بین LANهای مختلف یا اتصال به اینترنت را فراهم نمی‌کنند.
برای این کار به نوع دیگری از Network Device نیاز داریم.
این دستگاه Router است.
________________________________________
Routerها
می‌توانیم Switchها را به Routerها متصل کنیم و سپس Routerها را به اینترنت متصل کنیم.
وقتی End Hostهای LAN شعبه‌ی نیویورک بخواهند با End Hostهای LAN شعبه‌ی توکیو ارتباط برقرار کنند، داده را به Router خودشان، یعنی R1، ارسال می‌کنند.
R1 سپس داده را از طریق اینترنت به LAN شعبه‌ی توکیو ارسال می‌کند.
برای مثال، اگر PC1 در شعبه‌ی نیویورک بخواهد فایلی را از SRV1 در شعبه‌ی توکیو دریافت کند:
PC1 → SW1 → R1 → Internet → R2 → SW2 → SRV1
پاسخ نیز مسیر معکوس را طی می‌کند تا به PC1 برسد.
________________________________________
ویژگی‌های Router
اینها چند نمونه از Routerهای Cisco هستند که ممکن است در یک شبکه‌ی Enterprise مشاهده کنید.
مدل‌های ISR 1000 و ISR 4000 Interfaceهای شبکه‌ی خود را در قسمت پشتی دارند.
اما اگر به ISR 900 نگاه کنید، احتمالاً تفاوتی بین Router و Switch مشاهده می‌کنید.
بیایید یکی از Switchهایی را که قبلاً بررسی کردیم دوباره بیاوریم.
در مقایسه با Switch سری Catalyst 9200، روتر ISR 900 تعداد نسبتاً کمی Interface شبکه دارد.
این یکی از ویژگی‌های Routerها در مقایسه با Switchها است.
Routerها Interface کمتری نسبت به Switchها دارند.
همچنین به خاطر داشته باشید:
Switchها برای Forward کردن داده در داخل یک LAN استفاده می‌شوند.
اما Routerها برعکس این کار را انجام می‌دهند.
Routerها برای برقراری ارتباط بین LANها استفاده می‌شوند.
به همین دلیل:
Routerها برای ارسال داده از طریق اینترنت نیز استفاده می‌شوند.

Firewallها
حالا دوباره به شبکه‌ی خودمان برگردیم؛ اما این بار یک تفاوت وجود دارد.
یک مهاجم در جایی از اینترنت وجود دارد که مجموعه‌ای از روش‌های مختلف برای حمله به شبکه‌های ما در اختیار دارد تا اطلاعات را سرقت کند یا به شبکه‌ی سازمان آسیب برساند.
اگرچه Routerها می‌توانند برخی قابلیت‌های امنیتی پایه را نیز ارائه کنند، اما چیزی که واقعاً باید برای محافظت از شبکه‌هایمان استفاده کنیم:
Firewall — فایروال
است.
Firewallها دستگاه‌های تخصصی امنیت شبکه هستند که ترافیک ورودی و خروجی شبکه را کنترل می‌کنند.
Firewall می‌تواند:
•	در خارج از Router قرار گیرد، مانند FW1
•	یا در داخل شبکه قرار گیرد، مانند FW2
نکته‌ی مهم این است که Firewall از End Hostهای داخل شبکه، مانند PCها و Serverها، محافظت می‌کند.
Firewallها باید با Security Ruleها پیکربندی شوند تا مشخص شود:
•	کدام ترافیک شبکه اجازه‌ی عبور دارد
•	کدام ترافیک باید مسدود شود
اگر Ruleها را به‌درستی تنظیم کنیم، وقتی PC1 در شعبه‌ی نیویورک بخواهد به SRV1 در توکیو دسترسی پیدا کند، Firewall باید اجازه‌ی عبور این ترافیک را بدهد.
ترافیک برگشتی از SRV1 به PC1 نیز باید اجازه‌ی عبور داشته باشد.
اما اگر مهاجم تلاش کند به چیزی در شبکه‌های ما دسترسی پیدا کند، Firewall باید آن را مسدود کند.

Firewallهای Cisco

رابط‌ها و کابل‌ها
در ویدیوی قبلی درباره‌ی انواع مختلف دستگاه‌هایی که در شبکه‌ها پیدا می‌کنید صحبت کردیم.
این درس روی این موضوع تمرکز دارد که چگونه این دستگاه‌ها را به یکدیگر متصل می‌کنیم؛ به‌خصوص اینکه چگونه آنها را با استفاده از کابل به هم متصل می‌کنیم.
اتصالات بی‌سیم (Wireless Connections) نیز موضوع مهمی هستند که بعداً در دوره به آنها خواهیم پرداخت.

به این تصویر نگاه کنید.
این قسمت جلوی یک Switch است.

یادتان باشد که در جلسه‌ی قبلی یاد گرفتیم یکی از ویژگی‌های Switchها این است که معمولاً تعداد زیادی Interface دارند تا End Hostهایی مانند:

را به آنها متصل کنیم.

نگران نباشید.

RJ-45
حالا روی خود Interfaceها تمرکز کنیم.
این شکل را می‌شناسید؟
اگر کامپیوتر شما به یک شبکه‌ی سیمی (Wired Network) متصل باشد، تقریباً مطمئناً از پورتی شبیه این برای اتصال به شبکه استفاده می‌کند.
به این Portها:
RJ-45 Ports
گفته می‌شود.
RJ مخفف:
Registered Jack
است.
حالا به RJ-45 Connector که در انتهای کابل قرار دارد نگاه کنیم.
احتمالاً قبلاً یکی از آنها را دیده‌اید.
اینها نمونه‌هایی از کابل‌هایی هستند که دارای RJ-45 Connector هستند.
همان‌طور که می‌بینید، در طراحی و رنگ آنها تفاوت‌هایی وجود دارد، اما همه‌ی این Connectorها می‌توانند داخل Portهایی که در اسلاید قبلی دیدیم قرار بگیرند.
RJ-45 Connector در انتهای یک Copper Ethernet Cable استفاده می‌شود.
البته کابل‌های Ethernetای هم وجود دارند که از سیم مسی استفاده نمی‌کنند؛ بعداً به آنها خواهیم رسید.
________________________________________
Ethernet چیست؟
اما ابتدا Ethernet چیست؟
Ethernet یک پروتکل واحد نیست.
بلکه مجموعه‌ای از:
•	Network Protocols
•	Standards
است.
بنابراین Ethernet یک چیز واحد نیست و به همین دلیل تعریف دقیق آن کمی دشوار است.
برای اهداف این درس، تمرکز ما روی انواع کابل‌هایی است که توسط استانداردهای Ethernet تعریف شده‌اند.
همان‌طور که گفتیم، Ethernet شامل استانداردهای زیادی است، اما چون موضوع این درس Interfaces و Cables است، تمرکز ما نیز روی همین موارد خواهد بود.
جنبه‌های دیگر Ethernet را در درس‌های آینده یاد خواهیم گرفت.
________________________________________
Network Protocols — پروتکل‌های شبکه
قبل از اینکه استانداردهای کابل Ethernet را یاد بگیریم، بهتر است خیلی کوتاه توضیح دهیم که چرا به Network Protocols و Standards نیاز داریم.
فرض کنید دو نفر با یکدیگر صحبت می‌کنند.
یک نفر فقط انگلیسی بلد است و نفر دیگر فقط ژاپنی.
در این حالت احتمالاً ارتباط بسیار کمی بین آنها برقرار خواهد شد؛ شاید اصلاً نتوانند با یکدیگر ارتباط برقرار کنند.
چیزی که آنها نیاز دارند یک سیستم توافق‌شده برای برقراری ارتباط است؛ مثلاً یک زبان مشترک.
Network Protocolها همین نقش را برای Network Deviceها ایفا می‌کنند.
به همین دلیل استانداردهایی مانند Ethernet وجود دارند.

یک مثال مرتبط با کابل
فرض کنید می‌خواهید یک کابل را به یک Network Switch متصل کنید.

•	اندازه‌ی Connector
•	شکل Connector
•	اندازه‌ی Port
•	شکل Port
با یکدیگر توافق نکرده باشند، نمی‌توانید کابل را به Switch متصل کنید.
به همین دلیل Industry Standardهایی وجود دارند که تمام Vendorها از آنها پیروی می‌کنند.
این استانداردها هم شامل استانداردهای Physical مانند:
•	Connectorها
•	کابل‌ها
هستند و هم شامل استانداردهای Logical مانند:
IP — Internet Protocol
می‌شوند.

YouTube، همین ویدیو، سیستم‌عامل شما و تقریباً همه‌چیز در کامپیوتر در نهایت به شکل مجموعه‌ای از 0 و 1 است که کامپیوتر آنها را تفسیر می‌کند.
وقتی ارتباط از طریق یک کابل شبکه‌ی مسی برقرار می‌شود، تغییرات موجود در سیگنال الکتریکی توسط دستگاه دریافت‌کننده به‌عنوان 0 یا 1 تفسیر می‌شوند.
پس این یک Bit است.
اما Byte چیست؟
اینجا یک مجموعه‌ی 8 بیتی داریم:
8 bits = 1 byte
________________________________________
سرعت شبکه چگونه اندازه‌گیری می‌شود؟
سرعت با واحد:
Bits per second
اندازه‌گیری می‌شود.
فرض کنید یک Byte، یعنی 8 بیت، داده قرار است از طریق یک کابل ارسال شود.
این داده به دستگاه مقابل بیت‌به‌بیت می‌رسد.
یعنی انتقال در سطح شبکه به این صورت نیست که یک Byte کامل یک‌باره منتقل شود.
پس به خاطر داشته باشید:
سرعت شبکه با Bits per second اندازه‌گیری می‌شود، مانند:
•	Kilobits per second
•	Megabits per second
•	Gigabits per second
و نه Bytes per second.
البته داده‌های روی Hard Drive معمولاً با Bytes اندازه‌گیری می‌شوند.
بنابراین:
1 Gigabyte = 8 Gigabits
یعنی Gigabyte هشت برابر Gigabit است.
________________________________________
واحدهای اندازه‌گیری سرعت
بیایید چند مورد را مرور کنیم:
1 Kilobit = 1,000 bits
با اضافه کردن سه صفر:
1 Megabit = 1,000,000 bits
سه صفر دیگر:
1 Gigabit = 1,000,000,000 bits
و سه صفر دیگر:
1 Terabit = 1,000,000,000,000 bits
در سرعت‌های شبکه معمولاً واحدهایی بزرگ‌تر از این را نمی‌بینید و حتی Terabit نیز فعلاً خیلی رایج نیست.
البته سرعت شبکه‌ها دائماً در حال افزایش است و ممکن است سرعت‌های Terabits per second در آینده رایج شوند.
واحدهای بزرگ‌تر دیگری نیز وجود دارند:
•	Petabit
•	Exabit
•	Zettabit
•	Yottabit
اما نیازی نیست همه‌ی آنها را حفظ کنید، چون احتمالاً به این زودی‌ها سرعت شبکه‌ای در این مقیاس‌ها نخواهید دید.

Ethernet Standards — استانداردهای Ethernet
حالا بالاخره به استانداردهای Ethernet می‌رسیم.
این استانداردها در استاندارد:
IEEE 802.3
تعریف شده‌اند.
IEEE مخفف:
Institute of Electrical and Electronics Engineers
است.
خواهید دید که تمام این استانداردهای Ethernet با:
IEEE 802.3
شروع می‌شوند.
در اینجا جدولی از برخی استانداردهای IEEE برای کابل‌های مسی Ethernet داریم.
بعداً در همین درس کابل‌های Fiber Optic را نیز بررسی می‌کنیم.
در اینجا سرعت‌های رایج کابل‌های شبکه را داریم:
•	10 Mbps
•	100 Mbps
•	1 Gbps
•	10 Gbps
ستون بعدی نام‌های رایج آنها را نشان می‌دهد؛ نام‌هایی که معمولاً هنگام صحبت درباره‌ی Interfaceها، کابل‌ها و سرعت آنها در محیط کاری استفاده می‌شوند.
ستون بعدی استاندارد رسمی IEEE را نشان می‌دهد.
احتمالاً هنگام صحبت با Network Engineerهای دیگر از نام‌های رسمی IEEE استفاده نمی‌کنید، اما باید آنها را بشناسید.

10BASE-T، 100BASE-T، 1000BASE-T و 10GBASE-T
نام‌های غیررسمی این استانداردها عبارت‌اند از:
•	10BASE-T
•	100BASE-T
•	1000BASE-T
•	10GBASE-T
عدد ابتدای آنها به سرعت اشاره می‌کند.
اما BASE و T چه معنایی دارند؟
BASE به Baseband Signaling اشاره می‌کند.
جزئیات Baseband خارج از محدوده‌ی CCNA است، بنابراین فعلاً فقط معنای آن را بدانید.
حرف:
T
به:
Twisted Pair Cabling
اشاره می‌کند.
در ادامه‌ی درس درباره‌ی آن صحبت خواهیم کرد.

حداکثر طول کابل
آخرین مورد، Maximum Cable Length است.
توجه کنید که برای همه‌ی این استانداردها طول کابل:
100 meters
است.
این حداکثر طول برای کابل‌های Twisted Pair طبق Ethernet است و دلایل فنی و عملکردی دارد.
این اطلاعات ممکن است زیاد به نظر برسند، اما توصیه می‌کنم این استانداردها را حفظ کنید.
ممکن است دشوار به نظر برسد، اما با استفاده از Flashcardهای موجود در توضیحات ویدیو، حفظ کردن آنها بسیار ساده‌تر می‌شود.

UTP Cables
کابل‌های مسی مورد استفاده در استانداردهای Ethernet، UTP Cable هستند.
UTP مخفف:
Unshielded Twisted Pair
است.
Unshielded
یعنی سیم‌ها محافظ فلزی ندارند.
به همین دلیل ممکن است در برابر Electrical Interference آسیب‌پذیر باشند.
Twisted Pair
همان‌طور که در تصویر می‌بینید، چهار جفت سیم به دور یکدیگر پیچیده شده‌اند.
این پیچش به محافظت در برابر:
Electromagnetic Interference (EMI)
کمک می‌کند.
بنابراین داریم:
4 جفت سیم × 2 سیم = 8 سیم
در مجموع.

8 Pins
وجود دارد.
این دقیقاً با 8 سیم موجود در کابل مطابقت دارد.
اما همه‌ی استانداردهای Ethernet که قبلاً دیدیم از هر 8 سیم استفاده نمی‌کنند.

2 Pair = 4 Wires

1000BASE-T و 10GBASE-T

10BASE-T و 100BASE-T
فعلاً روی 10BASE-T و 100BASE-T تمرکز کنیم.
فرض کنید یک PC را با یک اتصال Fast Ethernet به یک Switch متصل کرده‌ایم.
اعداد نشان‌دهنده‌ی Pinهای RJ-45 روی Network Interface Card کامپیوتر و Interface مربوط به Switch هستند.
RJ-45 دارای 8 Pin است، اما چون این یک اتصال Fast Ethernet یا 100BASE-T است، فقط از 4 سیم یا 2 Pair استفاده می‌کنیم.
Pair اول:
Pin 1 و Pin 2
است.
این دو Pin به Pinهای 1 و 2 روی Interface مربوط به Switch متصل می‌شوند.
در نمودار ممکن است سیم‌ها صاف به نظر برسند، اما به خاطر داشته باشید که در یک کابل UTP، Pairها به دور یکدیگر پیچیده‌اند.
________________________________________
Tx و Rx
PC از:
Pins 1 & 2
برای Transmit Data استفاده می‌کند.
که آن را به شکل:
Tx
نشان می‌دهیم.
چون PC روی Pinهای 1 و 2 داده ارسال می‌کند، Switch نمی‌تواند روی همان Pinها ارسال کند.
Switch باید داده را روی Pinهای 1 و 2 دریافت کند:
Rx — Receive
پس نکته‌ی مهم این است:
PC / Server
روی:
Pins 1 & 2 → Transmit
و روی:
Pins 3 & 6 → Receive
کار می‌کند.
اما Switch برعکس است.
________________________________________
Pair دوم
Pair بعدی که در 10BASE-T و 100BASE-T استفاده می‌شود، 3 و 4 نیست.
بلکه:
Pin 3 و Pin 6
است.
عملکرد این Pair نسبت به Pair اول برعکس است.
در Switch:
Pins 3 & 6 → Transmit
و در PC:
Pins 3 & 6 → Receive
این باعث می‌شود بتوانیم از:
Full-Duplex Transmission
استفاده کنیم.
________________________________________
Full-Duplex
Full-Duplex یعنی:
هر دو دستگاه می‌توانند هم‌زمان داده ارسال کنند.
و به دلیل اینکه برای ارسال و دریافت از سیم‌های جداگانه استفاده می‌شود، مشکلاتی مانند:
Collision
رخ نمی‌دهد.
بنابراین هر دو دستگاه می‌توانند هم‌زمان داده ارسال کنند و مشکلی ایجاد نمی‌شود.
________________________________________
اتصال Router به Switch
حالا دستگاه سمت چپ را از PC به Router تغییر می‌دهیم.
همان‌طور که معمولاً:
PC → Switch
متصل می‌شود، معمولاً:
Switch → Router
نیز متصل می‌شود.
دوباره یک اتصال Fast Ethernet یا 100BASE-T داریم.
پس از Pairهای:
•	1 و 2
•	3 و 6
استفاده می‌کنیم.
Switch را از قبل می‌شناسیم:
Pins 1 & 2 → Receive
Pins 3 & 6 → Transmit
اما Router چطور؟
Network Interfaceهای Router دقیقاً مانند Network Interface کامپیوتر کار می‌کنند.
Router:
Pins 1 & 2 → Transmit
و:
Pins 3 & 6 → Receive
استفاده می‌کند.
بنابراین دوباره Full-Duplex داریم.
________________________________________
یک نکته‌ی بسیار مهم
این مورد را به خاطر بسپار:
Router
Transmit → 1, 2
Receive → 3, 6
PC
Transmit → 1, 2
Receive → 3, 6
Switch
Receive → 1, 2
Transmit → 3, 6
پس PC و Router از نظر Pinهای Tx/Rx مشابه هستند، اما Switch برعکس آنهاست.
________________________________________
Straight-Through Cable
وقتی دستگاه‌هایی مانند:
PC → Switch
یا:
Router → Switch
را به یکدیگر متصل می‌کنیم، چون Pinهای Transmit و Receive آنها در جهت مخالف هستند، یک کابل معمولی به‌خوبی کار می‌کند.
به این نوع کابل:
Straight-Through Cable
گفته می‌شود.
در یک Straight-Through Cable:
Pin 1 → Pin 1
Pin 2 → Pin 2
Pin 3 → Pin 3
و به همین ترتیب.
یعنی هر Pin در یک سر کابل مستقیماً به همان Pin در سر دیگر متصل است.
یک کابل Ethernet مسی دارای دو RJ-45 Connector است؛ یکی در هر طرف.
________________________________________
اما اگر دو دستگاه مشابه را متصل کنیم چه؟
در شبکه همیشه:
PC → Switch
یا:
Switch → Router
نداریم.
ممکن است بخواهیم:
•	Router → Router
•	Switch → Switch
•	PC → PC
را متصل کنیم.
فرض کنید دو Router را با یک کابل Straight-Through به هم وصل کنیم.
چه اتفاقی می‌افتد؟
ارتباط کار نمی‌کند.
چرا؟
چون Router سمت راست آماده‌ی دریافت داده روی Pinهای 1 و 2 نیست.
هر دو Router روی:
Pins 1 & 2 → Transmit
کار می‌کنند.
بنابراین Transmit یک دستگاه به Transmit دستگاه دیگر متصل شده است.
در نتیجه ارتباط برقرار نمی‌شود.
همین موضوع برای:
Switch → Switch
و:
PC → Router
نیز صادق است.
________________________________________
Crossover Cable
راه‌حل، استفاده از نوع دیگری از کابل است:
Crossover Cable
در Crossover Cable، Pin یک سر کابل مستقیماً به همان Pin در طرف دیگر متصل نمی‌شود.
در واقع Pairها در دو طرف جابه‌جا (Reversed) می‌شوند.
مثلاً:
Pin 1 → Pin 3
و:
Pin 2 → Pin 6
و در جهت معکوس:
Pin 3 → Pin 1
Pin 6 → Pin 2
به این ترتیب سیم‌ها روی یکدیگر Cross Over می‌شوند و به همین دلیل نام آن Crossover Cable است.
حالا:
Transmit یک دستگاه → Receive دستگاه دیگر
وصل می‌شود.
بنابراین دو دستگاه می‌توانند بدون مشکل با یکدیگر داده مبادله کنند.
برای مثال:
PC ↔ Router
اگر با Crossover Cable متصل شوند، می‌توانند با یکدیگر ارتباط برقرار کنند.
________________________________________
جدول مهم دستگاه‌ها
برای مرور:
Device	Transmit	Receive
Router	1, 2	3, 6
Firewall	1, 2	3, 6
PC	1, 2	3, 6
Switch	3, 6	1, 2
بنابراین Switch تنها دستگاه متفاوت در این گروه است.
بهتر است این موارد را حفظ کنید. Flashcardهای دوره نیز برای همین موضوع کمک زیادی می‌کنند.

Auto MDI-X
تمام این مطالب مهم هستند و حتی امروزه نیز ممکن است در شبکه‌ها مشکل ایجاد کنند.
اما یک نکته وجود دارد:
اکثر Network Deviceهای مدرن دیگر لازم نیست نگران Straight-Through یا Crossover Cable باشند.
دلیلش وجود قابلیتی به نام:
Auto MDI-X
است.
قبلاً اگر دو Switch را با Straight-Through Cable به یکدیگر متصل می‌کردید، نمی‌توانستند با یکدیگر ارتباط برقرار کنند.
اما Auto MDI-X به دستگاه‌ها اجازه می‌دهد به‌صورت خودکار تشخیص دهند دستگاه مقابل از کدام Pinها برای ارسال داده استفاده می‌کند.
سپس دستگاه خودش Pinهای مورد استفاده برای Transmit و Receive را تنظیم می‌کند.
در نتیجه دو دستگاه می‌توانند به‌صورت عادی داده ردوبدل کنند.
بنابراین اگر با تجهیزات بسیار قدیمی کار نمی‌کنید، معمولاً لازم نیست نگران تفاوت Straight-Through و Crossover باشید.
اما دانستن مفهوم Auto MDI-X هم برای آزمون CCNA و هم برای شبکه‌های واقعی مفید است.

این یکی از دلایلی است که این استانداردها می‌توانند با سرعت بسیار بالاتری کار کنند.

Fiber-Optic Connections — اتصالات فیبر نوری
تا اینجا درباره‌ی اتصال با کابل مسی UTP صحبت کردیم.
اما تکنولوژی جدیدتری وجود دارد که از بسیاری جهات برتر است:
Fiber Optic
برای مثال، کابل مسی UTP حداکثر تا حدود 100 متر قابل استفاده است.
این مقدار معمولاً برای داخل یک LAN کافی است.
اما برای شبکه‌های بزرگ‌تر چه؟
به این Cisco Switch نگاه کنید.
این Switch دارای:
24 RJ-45 Ports
است.
این همان Portهایی هستند که کابل مسی UTP به آنها متصل می‌شود.
اما این چهار Interface دیگر را ببینید.
حالا به این Cisco Router نگاه کنید.
این Router فقط چهار RJ-45 Port دارد.
بقیه‌ی Interfaceها شبیه آن چهار Port دیگر روی Switch هستند.
برای این Interfaceها چیزی به نام:
SFP Transceiver
استفاده می‌شود.
SFP مخفف:
Small Form-Factor Pluggable
است.
ابتدا SFP را داخل دستگاه قرار می‌دهیم.
اما هنوز یک مرحله باقی مانده است.
چه نوع کابلی به آن متصل می‌شود؟
پاسخ:
Fiber-Optic Cable

Fiber-Optic Cable
در Fiber Optic به جای ارسال Electrical Signal از طریق سیم مسی، داده به صورت Light از داخل رشته‌های شیشه‌ای منتقل می‌شود.
توجه کنید که در هر سر کابل دو Connector وجود دارد.
دلیلش این است که در هر طرف به یک اتصال برای:
Transmit
و یک اتصال برای:
Receive
نیاز داریم.
در کابل UTP مسی، از Pairهای مختلف سیم برای ارسال و دریافت استفاده می‌کردیم.
اما در Fiber Optic، از کابل‌های جداگانه برای Transmit و Receive استفاده می‌شود.
یعنی:
Transmit سمت چپ → Receive سمت راست
و:
Transmit سمت راست → Receive سمت چپ

ساختار Fiber-Optic Cable
حالا ساختار خود کابل را بررسی کنیم.
از مرکز کابل به سمت بیرون، چهار بخش داریم:
1. Fiberglass Core
هسته‌ی شیشه‌ای کابل.
نور از داخل این Core عبور می‌کند و داده را از یک دستگاه به دستگاه دیگر منتقل می‌کند.
2. Cladding
لایه‌ای که نور را منعکس می‌کند.
3. Protective Buffer
یک لایه‌ی محافظ که از Fiberglass در برابر شکستن محافظت می‌کند.
4. Outer Jacket
لایه‌ی بیرونی کابل.

دو نوع اصلی Fiber-Optic Cable داریم:
1.	Single-Mode Fiber
2.	Multimode Fiber

Multimode Fiber
در Multimode Fiber، هسته‌ی شیشه‌ای نسبت به Single-Mode پهن‌تر است.
این هسته‌ی پهن‌تر اجازه می‌دهد نور با زاویه‌های مختلف، که به آنها Mode گفته می‌شود، وارد Core شود.
در نمودار می‌توانید مسیرهای مختلف نور را ببینید که با زاویه‌های مختلف درون Core حرکت می‌کنند و از Cladding بازتاب می‌شوند.
ویژگی مهم
Multimode نسبت به UTP می‌تواند کابل‌های طولانی‌تری داشته باشد.
UTP به حدود 100 متر محدود است.
اما Multimode می‌تواند بیشتر از این مقدار را پوشش دهد.
با این حال، طول آن از Single-Mode کمتر است.
قیمت
Multimode Fiber از Single-Mode ارزان‌تر است.

Single-Mode Fiber
در Single-Mode Fiber، قطر Core از Multimode کمتر است.
یعنی رشته‌ی شیشه‌ای نازک‌تر است.
نور از طریق یک زاویه‌ی واحد یا Single Mode وارد می‌شود.
این نور توسط یک:
Laser-Based Transmitter
ارسال می‌شود.
در نمودار می‌توانید ببینید که نور تقریباً به‌صورت مستقیم در طول Core حرکت می‌کند.
طول کابل
Single-Mode می‌تواند طول کابل بیشتری نسبت به:
•	UTP
•	Multimode Fiber
پشتیبانی کند.
قیمت
Single-Mode از Multimode گران‌تر است.
دلیل اصلی آن استفاده از Laser-Based Transmitterهای گران‌تر است.

UTP در برابر Fiber-Optic
حالا دو نوع کابل را با هم مقایسه کنیم.
UTP
کابل‌های Copper UTP:
•	ارزان‌تر هستند.
•	حداکثر طول آنها حدود 100 متر است.
•	ممکن است در برابر EMI آسیب‌پذیر باشند.
•	پیچش سیم‌ها تا حدی در برابر EMI محافظت ایجاد می‌کند.
•	RJ-45 Portها ارزان‌تر از SFPهایی هستند که برای Fiber استفاده می‌شوند.
یک نکته‌ی امنیتی مهم نیز وجود دارد:
کابل UTP مقدار بسیار کمی سیگنال را به خارج از کابل منتشر یا Leak می‌کند.
این سیگنال بالقوه می‌تواند شناسایی شود و برای کپی کردن داده مورد استفاده قرار بگیرد.
بنابراین می‌تواند یک Security Risk ایجاد کند.
________________________________________
Fiber-Optic
Fiber-Optic:
•	گران‌تر از UTP است.
•	فاصله‌های بسیار بیشتری را پشتیبانی می‌کند.
•	SFP Portهای آن از RJ-45 گران‌تر هستند.
•	Single-Mode از Multimode گران‌تر است.
•	سیگنال را به خارج از کابل منتشر نمی‌کند.
بنابراین از این نظر، ریسک امنیتی ناشی از نشت سیگنال وجود ندارد.

Quiz 1
دو Router قدیمی را با یک کابل UTP به یکدیگر متصل کرده‌اید، اما داده با موفقیت بین آنها منتقل نمی‌شود.
مشکل چه می‌تواند باشد؟
A. آنها با Straight-Through Cable متصل شده‌اند.
B. آنها با Crossover Cable متصل شده‌اند.
C. آنها در حالت Auto MDI-X کار می‌کنند.
پاسخ صحیح: A
مشکل Crossover Cable نیست.
در واقع Crossover Cable احتمالاً مشکل را حل می‌کند.
چون هر دو Router روی Pinهای:
1 و 2 → Transmit
کار می‌کنند، به Crossover Cable نیاز داریم تا Transmit یک طرف را به Receive طرف دیگر یعنی:
3 و 6
متصل کند.
دستگاه‌های مدرن دارای Auto MDI-X چنین مشکلی ندارند.
اما ممکن است Routerهای قدیمی Auto MDI-X نداشته باشند.
بنابراین:
B ❌
Auto MDI-X به دستگاه‌ها اجازه می‌دهد تشخیص دهند دستگاه مقابل از کدام Pinها برای Transmit و Receive استفاده می‌کند و خودشان را با آن تطبیق دهند.
در واقع Auto MDI-X احتمالاً این مشکل را حل می‌کرد، اما چون Routerها قدیمی هستند ممکن است این قابلیت را نداشته باشند.
پس:
C ❌
در دستگاه‌های قدیمی بدون Auto MDI-X، برای اتصال دستگاه‌های هم‌نوع نمی‌توان از Straight-Through استفاده کرد.
باید از:
Crossover Cable
استفاده شود.
بنابراین:
A — Straight-Through Cable ✅

Quiz 2
شرکت شما می‌خواهد Switchهایی را که در دو ساختمان جداگانه قرار دارند به یکدیگر متصل کند.
فاصله‌ی دو ساختمان حدود:
150 متر
است.
اگر امکان داشته باشد، می‌خواهند هزینه را پایین نگه دارند.
چه کابلی باید استفاده کنند؟
A. UTP
B. Single-Mode Fiber
C. Multimode Fiber
پاسخ صحیح: C — Multimode Fiber
UTP ارزان‌تر است، اما نمی‌تواند مسافت بیشتر از 100 متر را پشتیبانی کند.
پس:
A ❌
Single-Mode می‌تواند مسافت بسیار بیشتری از 150 متر را پشتیبانی کند، اما از Multimode گران‌تر است.
پس:
B ❌
Multimode می‌تواند فاصله‌ی بیشتر از 150 متر را پشتیبانی کند و از Single-Mode ارزان‌تر است.
بنابراین:
C — Multimode Fiber ✅

Quiz 3
شرکت شما می‌خواهد دو دفتر را که حدود:
3 کیلومتر
از یکدیگر فاصله دارند، به هم متصل کند.
آنها می‌خواهند در صورت امکان هزینه را پایین نگه دارند.
چه کابلی باید استفاده کنند؟
A. UTP
B. Single-Mode Fiber
C. Multimode Fiber
پاسخ صحیح: B — Single-Mode Fiber
UTP ارزان است، اما فاصله‌ی 3 کیلومتر را پشتیبانی نمی‌کند.
پس:
A ❌

Quiz 4
یک Switch دارای این مشخصه روی Network Interfaceهای خود است:
Auto MDI-X
اگر آن را با یک Straight-Through Cable به یک Switch مشابه متصل کنیم، چه اتفاقی می‌افتد؟
A. به‌صورت عادی کار می‌کنند.
B. با سرعت کمتری کار می‌کنند.
C. نمی‌توانند با یکدیگر ارتباط برقرار کنند.
پاسخ صحیح: A
آنها با سرعت کمتر کار نمی‌کنند.
Portها دارای:
Auto MDI-X
هستند.
حتی اگر Auto MDI-X هم نداشتند، با سرعت کمتر کار نمی‌کردند؛ بلکه اصلاً ارتباط برقرار نمی‌شد.
بنابراین:
B ❌
از آنجا که Portها Auto MDI-X دارند، می‌توانند حتی با Straight-Through Cable نیز با یکدیگر ارتباط برقرار کنند.
بنابراین:
C ❌
با وجود Auto MDI-X، Switchها بدون توجه به اینکه با:
•	Straight-Through
•	Crossover
متصل شده باشند، به‌صورت عادی کار می‌کنند.
پس:
A — They would operate normally ✅

Quiz 5
شرکت شما نیاز دارد تعداد زیادی End Host را به یک Switch متصل کند.
Switch در یک Wiring Cabinet در همان طبقه‌ی اداری قرار دارد.
چه نوع کابلی باید استفاده شود؟
A. UTP
B. Single-Mode Fiber
C. Multimode Fiber
پاسخ صحیح: A — UTP
بیشتر Hostها قابلیت اتصال به Switch از طریق Fiber را ندارند.
همچنین بیشتر Switchها تعداد کافی SFP Interface برای اتصال تعداد زیادی Host ندارند.
پس:
B — Single-Mode Fiber ❌
C — Multimode Fiber ❌
کابل UTP استاندارد اتصال سیمی End Hostها به Switchها است.
Switchها معمولاً تعداد زیادی RJ-45 Port برای اتصال End Hostها دارند.
End Hostها نیز معمولاً روی Network Interface Card خود یک RJ-45 Port دارند تا کابل UTP به آن متصل شود.
بنابراین:
A — UTP ✅
